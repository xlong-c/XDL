Why

1. 先想清楚: 模型怎么"记住"前面读过的东西

这一节不需要任何公式, 只要一个生活类比. 读小说读到第 500 页提到"那把钥匙", 你能想起它是第 30 页出现过的, 是因为脑子里一直留着一份前情记忆. 语言模型也要解决同样的问题: 处理当前这个词时, 怎么用上前面所有词的信息?

思路 怎么存历史 优点 代价
RNN 把所有历史压进一个固定向量 hₜ 内存恒定, 推理快 序列一长, 早期信息被挤掉, 容易忘
注意力 每个 token 原样全部留着 几乎不丢信息, 效果强 序列翻倍, 计算和显存翻四倍 (O(T²))
GDN 固定大小记忆矩阵 Sₜ, 支持定向读 / 写 / 遗忘 内存恒定, 又比朴素 RNN 记得准 写入规则更复杂, 需要专门推导才能高效训练
GDN 的野心一句话: 用一块固定大小的记忆, 尽量逼近注意力的记忆质量, 同时保住 RNN 那种"内存不随序列变长而爆炸"的优势.

Memory

2. 这块"记忆"到底是什么: 一张 key → value 的关联表

很多人卡在 S ∈ R^{Dk×Dv} 这种符号, 不知道它对应现实里的什么. 其实它就是一张关联表, 类比查字典最直观: 想记住"看到线索 A 就想起内容 X", 就把 (A, X) 存进矩阵 S; 以后拿出线索 A (或跟 A 很像的线索) 就能取回 X.

这里的"线索"就是 key k, "内容"就是 value v. 写入和读取各对应一个最基础的线性代数操作:

写

写入 = 外积

S = S + k ⊗ v. 外积 k ⊗ v 生成一个 [Dk × Dv] 矩阵, 把"线索 k 的方向"和"内容 v"绑在一起, 叠加到 S 上, 相当于在表里新增一行"看到 k 就回忆 v".

读

读取 = 点积

read = Sᵀ k. 在做"线索匹配": 查的线索和写入时的 k 方向越一致, 点积越大, 取回的内容越接近原来的 v; 完全不相关就接近读不出东西.

记一个张量朝向: 本目录代码把每个 head 的状态存成 [Dk, Dv], 所以读写成 Sᵀ k, 写写成 k ⊗ delta. 这只是实现摆放方向, 数学没变.
到这里你已经懂了"线性记忆"的核心: 写入靠外积叠加, 读取靠点积检索. 普通线性注意力就是不停 S = S + kₜ ⊗ vₜ 把每个 token 硬叠进去. 下一节看它有什么毛病.

Delta Rule

3. 怎么往记忆里写: 从"硬塞"到"先读再纠错"

第 2 节里的写入 S = S + kₜ ⊗ vₜ 叫 additive (加法) 更新, 简单, 但有个明显问题.

朴素加法的毛病: 同一个线索反复出现时, 相似 key 不断往同一方向叠加, 这块区域会被"写爆", 数值越堆越大; 已经记对的内容也会被后来的写入反复干扰. 加法更新只会"往里塞", 不会"检查塞得对不对".
delta rule 的核心: 做事前先检查现状. 先读一遍记忆现在会回答什么, 只把"真实值和已记内容的差距"写回去. 这就是在线纠错, 也是 GDN 比朴素线性注意力记得更准的根本原因.
read_t = Sᵀ kₜ # 1. 先用当前 key 读: 现在的记忆会回答什么? delta_t = beta_t * (v_t - read_t) # 2. 只取"真实值与已记内容的差距" S = S + kₜ ⊗ delta_t # 3. 把这个差距写回去

关键就在第 2 步的 v_t - read_t:

A

记对了 → 几乎不写

如果记忆已经记对, read_t 接近 v_t, 差距接近 0, 这一步几乎什么都不写, 不浪费也不污染.

B

记错了 → 用力修正

如果记错或还没记, 差距很大, 这一步就用力修正, 而且主要沿当前 kₜ 的方向改.

C

beta_t 是写入强度旋钮

beta_t ∈ [0, 1]: 越接近 1 越相信当前这步的修正, 越接近 0 越保守.

一句话记住 delta rule: 它不是"再塞一份新值进去", 而是"看看哪里还没记对, 只补那部分".

Gated

4. 最后一块拼图: 给记忆装"遗忘开关" → Gated DeltaNet

delta rule 解决了"写得准", 但它默认旧记忆永远不褪色. 现实里我们往往希望旧信息随时间慢慢淡出, 给新信息腾地方 —— 这正是 RNN 里"门控 (gating)"做的事, 也是 GDN 里那个 "Gated" 的来历.

做法很简单: 每一步先让整块记忆乘上一个 (0, 1] 之间的衰减系数 exp(g_t), 再做 delta 写入:

S_t^- = exp(g_t) * S_{t-1} # 先按遗忘门衰减旧记忆 read_t = (S_t^-)^T k_t # 在衰减后的记忆上读 delta_t = beta_t * (v_t - read_t) # 只补差距 S_t = S_t^- + k_t ⊗ delta_t # delta 写入 o_t = S_t^T q_t # 用 query 从新记忆里读出本步输出
g_t 是遗忘门: 实现里先把它参数化成负数再取 exp, 保证 exp(g_t) ∈ (0, 1] —— 每步只"保留一部分"旧记忆, 不会放大到发散.
为什么最后用 q_t 不用 k_t: 写入用 key 决定"刻在记忆哪个方向", 读输出用 query 决定"从哪个方向取". 和注意力里 Q/K 的分工一致.
把三件事拼起来就是 Gated DeltaNet 的完整单步: 衰减旧记忆 (遗忘门) → 读一遍 → 只写差距 (delta rule) → 从新记忆读输出.
机制 状态更新 读历史方式 直觉
普通 additive 直接累加新值 从累计状态线性读出 只塞不查, 容易堆乱
delta rule 按残差修正写入 先读旧记忆再修正 在线纠错
Gated DeltaNet 衰减门 + delta 写入 同时有遗忘和纠错 本文实现对象
数学核心到此讲完. 从下一节开始是更紧凑的等价写法和工程实现 (recurrent / chunkwise), 你想动手读代码或对照论文时再深入.

Rule

5. 紧凑写法与代码朝向

第 1~4 节已经把 GDN 的单步逻辑讲清楚了. 这一节把同一套数学换成更适合"对照代码"和"推导等价性"的紧凑写法. 只想要直觉的话, 看到这里就够了; 想动手读代码再继续往下.

S_t^- = exp(g_t) * S_{t-1} read_t = (S_t^-)^T k_t delta_t = beta_t * (v_t - read_t) S_t = S_t^- + k_t outer delta_t o_t = S_t^T q_t
`beta_t` 在管什么: 写入强度. 如果它接近 0, 本步更像“读一下再轻微修正”.
`g_t` 在管什么: 衰减门. 因为实现里通常把它写成负数后再 `exp`, 所以它更像对旧状态的保留系数.
为后面证明先做个记号替换: 如果记 alpha_t = exp(g_t), 那么整步更新也可以压成 S_t = alpha_t (I - beta_t k_t k_t^T) S_{t-1} + beta_t k_t v_t^T. chunkwise 的推导就是围绕这个更紧凑的写法展开的.
A

为什么要先读再写

如果旧记忆已经能很好给出 v_t, 那么 v_t - read_t 会很小, 这一步几乎不用更新. 所以 GDN 更像在线纠错, 而不是每步都把一份新值重新塞进状态里.

B

为什么写入是 rank-1 update

k_t outer delta_t 只沿当前 key 方向修改状态. 这让每一步更新既便宜, 也保留了“这个修正属于哪类 key”的结构信息.

C

为什么输出从新状态里读

公式里是 o_t = S_t^T q_t, 不是从 S_{t-1} 读. 也就是说, 当前 token 的写入可以立刻影响本步输出.

Chunkwise

6. 为什么训练时要改写成 chunkwise

逐 token 递推很好懂, 但太串行. chunkwise 的目标不是改数学结果, 而是把“块内可并行的部分” 和“块间必须携带的状态”拆开.

换的不是模型, 是展开顺序: recurrent 是按 token 展开, chunkwise 是把块内很多步先折叠成矩阵算子, 块间仍只传一个状态.
真正保留串行的地方: 不是整条序列, 而是 chunk 边界上的 S. 这就是它能更适合训练并行的原因.
1

块内先算 intra-chunk

把当前 chunk 内部的递推改写成矩阵形式, 让这部分尽量并行.

2

块间只传递 `S`

上一块结束后的最终状态继续流向下一块, 这部分对应 inter-chunk 读写.

3

结果仍然对齐 recurrent

教学版最重要的检查项就是: `chunkwise` 输出要和 `recurrent` 输出保持数值一致.

`g.cumsum`

把逐步衰减改成前缀量

这样块内任意两个位置之间的衰减都能用前缀差直接算出来, 不必再手写一层时间循环.

`decay_mask`

块内因果衰减矩阵

它编码了 “位置 j 对位置 i 的贡献在经过多次遗忘后还剩多少”.

`v_new`

真正还要写的新残差

先扣掉跨块旧状态已经能解释的部分, 剩下的才值得在当前块里继续写入.

名字容易误导: 代码里的 attn 不是常规 Transformer 里的 softmax 注意力, 更像是块内下三角递推被一次性展开后的线性算子.

Equivalence

6.1 为什么 recurrent 和 chunkwise 算的是同一件事

关键不是“它们长得像”, 而是 chunkwise 只是把 chunk 内的逐步残差写入, 改写成了一个下三角线性系统的显式求解.

A

先把块内状态展开

记 gamma_r = Π alpha_m, 其中 alpha_r = exp(g_r). 那么 chunk 内第 r 步后的状态总能写成:

S_r = gamma_r S_0 + Σ_{j=1}^r (gamma_r / gamma_j) * k_j outer u_j

也就是 “入口状态经过累计衰减后的贡献” 加上 “块内每次 rank-1 修正的累计贡献”.

B

再把写入残差写成下三角系统

每个 u_r = beta_r (v_r - read_r) 都只依赖更早的 u_1 ... u_{r-1}, 所以整块其实满足:

(I + L) U = V_beta - K_{beta,gamma} S_0

这里 L 是严格下三角矩阵. 这正是“块内递推可以一次性 materialize”的数学原因.

C

chunkwise 只是显式解它

代码里的 decay_mask 提供 gamma_r / gamma_j, attn 对应 (I + L)^{-1}, v_new 就是解出来的那组真实残差写入 U.

一旦块内每个残差写入都和 recurrent 相同, 输出 inter + intra @ v_new 和块末状态也自然完全相同.

所以误差从哪来: 在精确算术下二者完全等价. demo 里看到的微小差异只来自浮点舍入和运算重排顺序不同.

Implementation

7. 教学实现边界

本目录只实现“足够讲清主线”的那一层. 这也是它为什么适合放在 learn/ 而不是直接接进主框架.

保留 recurrent rule, chunkwise rule, output gate, head-wise `g` / `beta`. 省略 causal conv mixing, fused CUDA kernel, hybrid full attention, registry 接入.
边界提醒: 这里的 SimpleGatedDeltaNet 是教学 block, 不是完整 Qwen3-Next 复刻版.

Code

8. 代码导读

如果你准备直接进代码看, 下面这张地图会省点来回翻找的力气.
