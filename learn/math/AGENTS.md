# learn/math - 数学教程规范

## 目录职责

- `learn/math/` 存放面向学习和工程实践的数学教程, 包括高等数学, 线性代数, 概率统计, 优化, 矩阵微积分和单篇专题.
- 本目录内容服务于理解深度学习, 数值计算和量化实验中的数学工具, 不直接定义 XDL 框架 API.
- 数学教程可以比 `docs/` 更长, 更解释性, 但必须保持可验证, 可维护, 可继续扩写.
- 改动本目录下教程, HTML, CSS, 图片生成脚本或资产前, 先用 `find` / `rg` 查看现有文件结构, 链接关系和同类页面写法.

## 内容定位

- 读者默认是有基础编程能力, 正在补数学和机器学习底层知识的人.
- 教程不是公式手册, 也不是课堂板书转写. 它必须回答三个问题: 这个概念解决什么问题, 数学上怎样定义, 工程或机器学习里怎样用.
- 每个课程都要有清晰主线. 例如高等数学按 "函数 -> 极限 -> 连续 -> 导数 -> 积分" 推进, 线性代数按 "方程组 -> 矩阵 -> 向量空间 -> 变换 -> 分解" 推进.
- 单篇专题必须说明它和相邻数学模块的关系, 例如 Hessian 应连接微积分, 线性代数, 优化和深度学习 loss landscape.

## 教程写作原则

- 先讲问题, 再讲定义.
- 先讲直觉, 再讲公式.
- 先讲几何或统计意义, 再讲代数推导.
- 先讲适用条件, 再讲计算套路.
- 先给最小例子, 再推广到抽象形式.
- 先把符号说清楚, 再使用符号.
- 每个定理, 公式或方法都要交代前提条件, 结论和不能滥用的边界.
- 不写只堆公式的章节. 如果一段连续出现多个公式, 中间必须插入解释, 说明符号含义和它在主线中的作用.
- 不把 "在深度学习中有用" 当成空泛结论. 必须说明它具体落在哪类问题上, 例如优化, 泛化, 概率建模, 采样, 正则化, 量化或不确定性估计.

## 推荐章节结构

正式章节建议按下面顺序组织, 可以按主题裁剪, 但不要丢掉主线:

1. 标题和一句话定位.
2. 本章要解决什么问题.
3. 前置知识和本章不展开的内容.
4. 主线图或路线表.
5. 直觉解释和具体例子.
6. 严格定义, 符号说明和适用条件.
7. 核心定理, 性质或计算方法.
8. 推导或证明草图. 如果证明太长, 写清关键想法和跳过原因.
9. 典型例题, 包括至少一个可手算的小例子.
10. 几何图像, 概率图像或数值实验.
11. 和机器学习, 深度学习或数值计算的连接.
12. 易错点, 检查清单和本章总结.
13. 可选练习或继续阅读.

课程总纲 `outline.md` 应负责课程路线, 章节定位和扩写清单, 不承载过长正文. 正式章节正文应放在对应课程目录的独立文件中.

## 数学表达规范

- 公式使用 LaTeX. 行内公式用 `$...$` 或 `\(...\)`, 独立公式用 `$$...$$` 或 `\[...\]`, 同一文件内尽量保持一致.
- 第一次出现变量时必须解释含义, 维度, 取值范围和默认假设. 例如 `x \in \mathbb{R}^n`, `A \in \mathbb{R}^{m \times n}`, `p(x)` 是否为密度函数.
- 涉及极限, 导数, 积分, 交换求导积分, 条件概率, 独立性, 凸性, 正定性, 特征分解等内容时, 必须写明成立条件.
- 不把近似写成等号. 泰勒展开, 大 O 记号, 数值近似和经验结论要明确使用 `\approx`, `O(...)`, "近似为" 或 "在 ... 条件下".
- 定义, 定理, 推论, 例子和注意事项要在文本上区分清楚, 避免把直觉解释写成严格结论.
- 对容易混淆的概念要主动对照, 例如连续和可导, 相关和独立, 协方差矩阵和相关矩阵, 特征值和奇异值, Hessian 和 Fisher 信息矩阵.

## 文件和命名规范

- 新课程放在 `learn/math/<course_name>/`, 目录名使用小写 `snake_case`.
- 单篇专题可以放在 `learn/math/` 根目录, 但如果专题需要多个章节, 图片或脚本, 应迁移到独立课程目录.
- 课程章节 HTML 推荐使用 `chapterNN_topic.html`, 已有课程可以继续沿用 `sessionN.html`, 但同一课程内必须保持一致.
- 课程蓝图使用 `outline.md`. 如果 Markdown 只是旧草稿且 HTML 已成为唯一维护入口, 应删除旧 Markdown 或明确标记为仍维护的源文件, 不允许留下失效链接.
- 图片放在课程内 `assets/` 目录. 若是跨课程通用图, 才放在 `learn/math/assets/`.
- 图片命名使用 `<course>_<chapter>_<topic>.png` 或现有课程前缀, 例如 `ps_ch08_likelihood_curve.png`, `highmath_function_limit.png`.
- 图片生成脚本命名使用 `gen_<chapter_or_topic>_figs.py`, 放在对应 `assets/` 目录或既有脚本目录中.

## HTML 教程规范

- 新增或重构 `learn/math/**/*.html` 和 CSS 前, 必须先阅读 `docs/md/HTML_STYLE.md`.
- HTML 是给人类阅读的可视化层. 它可以提炼和重排内容, 但不能引入和 Markdown 源, 课程总纲或源码脚本冲突的新事实.
- 课程 CSS 应复用 `docs/html/assets/xdl-doc.css` 的主题 token 和公共数学/教程组件. 课程 CSS 只作为薄入口和课程独有组件扩展,不复制 topbar,hero,layout,toc,card,table,formula,practice,chapter-nav 等公共样式.
- 需要主题切换时复用 `docs/html/assets/xdl-theme.js`.
- 页面导航只能指向真实存在的文件和锚点. 删除 Markdown 草稿时, 必须同步清理 HTML 中的 "Markdown 原文", "总纲" 等失效链接.
- 数学渲染脚本可以沿用课程已有方案. 不要为了单页随意更换 MathJax, KaTeX 或 CDN 来源.
- 每张图都要有有效 `alt` 文本或紧邻说明, 说明图要表达的数学关系, 不能只写 "figure".
- HTML 页面底部应提供上一章, 下一章或返回课程入口的导航. 如果课程入口不存在, 不要伪造链接.

## 图像和数值实验规范

- 抽象概念优先配图, 尤其是极限, 导数, 积分, 线性变换, 特征分解, 分布, 采样, 损失曲面和优化轨迹.
- 图像应服务于理解, 不做装饰性插图.
- 生成图像时优先写可复现脚本, 使用固定随机种子, 明确输出路径.
- Python 画图脚本使用代码内显式配置, 不引入命令行参数解析库.
- 生成脚本要有顶部 docstring, 写明用途, 运行命令和输出文件.
- 图中的坐标轴, 标题, 图例和注释要能帮助读者理解数学含义. 不要只输出裸曲线.
- 不提交临时缓存, notebook 执行产物或 `__pycache__`.

## 代码示例规范

- 代码示例必须最小可运行, 不依赖隐藏上下文.
- Python 示例要有类型注解, 除非是极短的交互式片段.
- PyTorch, NumPy, SciPy 等第三方 API 如果涉及最新行为或容易变化的用法, 先查官方文档再写.
- 示例应优先验证数学结论, 例如数值 Hessian 对拍解析 Hessian, Monte Carlo 估计对拍理论期望, 梯度下降轨迹对拍等高线图.
- 不为了展示而引入大型依赖, 网络下载或长时间训练.

## 质量检查清单

提交或结束修改前至少检查:

- `find learn/math -maxdepth ...` 能说明新增文件位置合理.
- `rg` 搜索旧文件名和旧链接, 确认没有指向已删除文件的引用.
- Markdown 标题层级连续, 链接和图片路径有效.
- HTML 页面导航指向真实文件, CSS 和脚本路径正确.
- 公式符号已经解释, 条件没有遗漏, 近似没有误写成等式.
- 每章至少有 "本章解决什么", "核心主线", "易错点或检查清单", "总结" 中的主体部分.
- `git diff --check` 通过, 没有尾随空格或格式错误.

## 不允许的做法

- 不允许在不同文件中长期维护两份内容相同但不同步的教程正文.
- 不允许把旧 Markdown 留在目录里, 同时 HTML 链接仍指向它但没人维护.
- 不允许新增只有标题和空清单的课程骨架, 除非明确标记为待办且不从首页导航暴露给读者.
- 不允许在数学结论上省略关键前提, 例如把 "可导一定连续" 反过来说, 或把 "独立推出不相关" 写成等价.
- 不允许复制外部教材大段内容. 可以参考结构和标准定义, 但正文必须重新组织, 并以本仓库的学习主线表达.
- 不允许用装饰性 HTML 替代数学解释. 页面好看不能弥补主线不清, 条件不明或公式错误.
