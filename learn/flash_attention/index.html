FlashAttention 可视化教程

从 Naive Softmax → Online Softmax → Attention Baseline → FlashAttention v1 → FA2

01. Softmax — 从 Naive 到 Safe

理解数值稳定性：为什么要减去 row max

Softmax 定义

softmax(xᵢ) = exp(xᵢ) / Σⱼ exp(xⱼ)

问题：当 x 很大时，exp(1000) 会溢出；x 很小时会下溢为 0。

NaN / inf
Naive Softmax 大值输入
[0.09, 0.24, 0.67]
Safe Softmax 输出

Safe Softmax 公式

m = max(x) softmax(xᵢ) = exp(xᵢ - m) / Σⱼ exp(xⱼ - m)
关键洞察：分子分母同时除以 exp(m)，数学结果不变，但 exp(xᵢ − m) 最大值是 exp(0) = 1，永远不会溢出。

本节 Kernel 对比

// Naive — 会溢出
numerator = tl.exp(row)
denom = tl.sum(numerator)
output = numerator / denom

// Safe — 先减 row max
row_max = tl.max(row)
numerator = tl.exp(row - row_max)
denom = tl.sum(numerator)
output = numerator / denom
和 Attention 的关系：标准 attention 每一行都是一个 softmax — probs[row,:] = softmax(scores[row,:])。后续 FlashAttention 只是避免把完整 scores/probs 写到 HBM。

02. Online Softmax — 分块 Streaming 更新

FlashAttention 的核心积木：用两个标量状态替代全局信息

Safe Softmax 的局限

需要先读完一整行才能知道 m = max(row) 和 l = Σ exp(x − m)。如果一行太长（如 seq_len=128K），无法一次放入 SRAM。

分块合并公式

已有状态: m_old = max(旧 blocks) l_old = Σ exp(x_old − m_old) 新来一个 block: m_block = max(block) l_block = Σ exp(block − m_block) 合并: m_new = max(m_old, m_block) l_new = exp(m_old − m_new) · l_old + exp(m_block − m_new) · l_block
关键：只需要保存两个标量 (m, l)，就能分块累加出精确结果。这就是 "online" — 不需要回头看旧数据。

两遍扫描策略

第一遍：扫描所有 block，维护 (running_max, running_sum)
每个 block 算完就合并到全局状态，不需要保留 block 数据。
第二遍：用最终的 (m, l) 写出概率
重新读取每个 block，用统一的 m 和 l 计算 softmax 输出。
对 Attention 的启发：Attention 中每个 query row 不仅需要分母，还需要 O = Σ softmax(scoreⱼ) · Vⱼ。所以 FlashAttention 保存的状态扩展到三个：(m, l, acc)，其中 acc 是 V 的加权累积。

03. Attention Baseline — 显存灾难

看清楚为什么 materialize N×N 矩阵不可行

标准 Scaled Dot-Product Attention

S = Q · Kᵀ / √d ← [batch, heads, N, N] P = softmax(S) ← [batch, heads, N, N] O = P · V ← [batch, heads, N, d]

S + P 显存爆炸

seq_len NS + P (fp16)说明
1,024128 MiB尚可接受
2,048512 MiB开始吃力
4,0962 GiB单层已很大
8,1928 GiB加上 Q/K/V/O 就爆了
32,768128 GiBA100 80G 直接 OOM

计算方式：batch=1, heads=32, N×N×2 tensors×2 bytes = 128N² bytes

Baseline 的 3 个 Triton Kernel

// Step 1: QKᵀ → 写出完整 S [N×N]
_scores_kernel(q, k, scores_ptr)

// Step 2: softmax(row) → 写出完整 P [N×N]
_row_softmax_kernel(scores_ptr, probs_ptr)

// Step 3: P·V → 写出 O [N×d]
_pv_kernel(probs_ptr, v, out_ptr)
为什么这里故意这样写？目的是用 Triton 看清楚 baseline 的 HBM 读写成本 — 每一步都要把巨大的 N×N 矩阵写回显存再读回来。

常见误区：FlashAttention 不是 sparse attention 或近似 attention。数学结果和普通 attention 完全一致，只是 IO 方式不同。
v1 的局限：非 matmul FLOPs 偏多；batch×heads 小时 thread blocks 不够多；block 内 warp 分工有额外 shared memory 通信。这些是 FA2 要改的。

05. Triton Fused Softmax

把一行 softmax 映射到一个 Triton program

Triton 编程模型映射

概念Triton 对应
一个 program一行 row
tl.arange该行的列索引
tl.load读入一行
tl.max行最大值
tl.exp分子
tl.sum分母
tl.store写出结果
Fused Softmax 在一个 kernel 里完成: max → exp → sum → divide 不需要多个 op 之间反复读写全量 tensor
为什么这里单独写 softmax kernel？FlashAttention 的 forward kernel 本质就是 QK matmul tile + row softmax update + PV matmul tile。看懂 Triton 的 row program 再看 FlashAttention 的 Q block program 会容易很多。

06. FlashAttention-2 — Work Partitioning 优化

在 FA v1 基础上优化并行度和 warp 分工

FA2 改进的三个维度

①
减少 non-matmul FLOPs

减少 online softmax 的 rescale 开销

②
增加并行度

batch×heads 小时也有足够 thread blocks

③
改善 warp 分工

减少 shared memory 往返

FA2 Launch Grid

grid x: Q blocks along sequence // cdiv(N, BLOCK_M) grid y: batch * heads // each (b,h) independent each program: owns one Q block loops over all K,V blocks keeps m, l, acc on chip writes one O block
