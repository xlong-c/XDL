Quantization / Orthogonal Rotation / Hadamard

Hadamard 变换: 把难量化的 outlier 打散

这份教程用一个可拖动的小实验解释 Hadamard 在低比特大模型量化里的作用: 它不是量化器本身, 而是在量化前换一个坐标系, 让 activation 和 weight 的数值分布更均匀.

打开交互演示 看 PyTorch 实验 量化笔记
核心问题 INT4/INT8 的 scale 被极端值拉大, 普通值会被压扁.
核心操作 用归一化 Hadamard 矩阵做正交旋转, 再量化旋转后的张量.
核心保证 不量化时 xW = (xH)(HᵀW), 数学输出不变.

Start

0. 这页解决什么

低比特量化最难的地方之一不是公式复杂, 而是数值分布太偏. LLM 的部分 activation channel 会出现特别大的值, 少数 outlier 直接决定量化 scale, 导致大多数普通值的有效精度很差. Hadamard 变换常被用来做量化前的数值整形.

Problem

1. 量化为什么怕 outlier

对称 per-tensor INT4 量化通常会让最大绝对值决定 scale. 如果一个向量里有一个特别大的值, scale 会变大, 其他普通值除以 scale 后接近 0, round 之后直接丢信息.

qmax = 2^(bits - 1) - 1 scale = max(abs(x)) / qmax q = clamp(round(x / scale), -qmax - 1, qmax) x_hat = q * scale
关键风险: INT4 只有很少的离散档位. 一个 outlier 会让档位间距变大, 小值会被粗暴地挤到同一个量化桶里.

Hadamard

2. Hadamard 是什么

Hadamard 矩阵只由 +1 和 -1 组成. 归一化后它是正交矩阵: HᵀH = I. 它会把每个输出维度写成多个输入维度的加减组合, 所以能把集中在单个 channel 的大值分散出去.

直觉: Hadamard 没有删除信息, 只是把坐标轴换掉. 原来一个维度特别尖, 旋转后多个维度一起承担这部分能量.

Linear

4. 为什么能塞进 Linear 层

Transformer 里大量计算都是 Linear. 对任意正交矩阵 R, 都有 RRᵀ = I. 因此可以把原始 xW 改写成 (xR)(RᵀW).

y = xW = xIR = xRRᵀW = (xR)(RᵀW)
不量化时

两条路径数学等价, 输出完全一样. Hadamard 只是换坐标系.

量化时

quantize(x) 和 quantize(xH) 的误差不同. 如果 xH 更均匀, 量化误差通常更小.

工程上

HᵀW 可以离线预处理到权重里; 但 activation 上的 Hadamard 仍可能需要高效在线 kernel.

Placement

5. LLM 里通常放在哪里

Hadamard 不能随便跨过非线性, softmax, RoPE 或归一化层. 它通常放在能保持线性等价的位置, 或作为权重量化前的离线预处理.

1

Linear 输入 activation 前

用 xH 替代 x, 同时把 Hᵀ 吸收到权重左侧, 缓解 activation outlier.

2

Attention value / output 路径

对 value 或 attention output 做旋转, 再在相邻投影权重中抵消逆变换.

3

MLP 中间激活

在 down projection 之前处理中间激活, 但必须避开无法线性穿越的 activation function 边界.

4

权重量化前

把权重分布旋转得更均匀, 再结合 GPTQ, AWQ, group-wise quantization 等方法做低比特压缩.

Code

6. PyTorch 最小实验

下面这段代码复现页面里的逻辑. 它不是生产级 kernel, 只是用来验证: xW 与 (xH)(HᵀW) 等价, 以及量化误差如何受分布影响.

import torch def hadamard_matrix(n: int, device=None, dtype=None) -> torch.Tensor: assert n > 0 and (n & (n - 1)) == 0, "n must be power of 2" h = torch.tensor([[1.0]], device=device, dtype=dtype) while h.shape[0] < n: h = torch.cat( [torch.cat([h, h], dim=1), torch.cat([h, -h], dim=1)], dim=0, ) return h / (n ** 0.5) def quantize_dequant_symmetric(x: torch.Tensor, bits: int = 4) -> torch.Tensor: qmax = 2 ** (bits - 1) - 1 scale = torch.clamp(x.abs().max() / qmax, min=1e-8) q = torch.round(x / scale).clamp(-qmax - 1, qmax) return q * scale torch.manual_seed(0) batch, hidden, out_features = 128, 1024, 1024 x = torch.randn(batch, hidden) W = torch.randn(hidden, out_features) x[:, :8] *= 40 H = hadamard_matrix(hidden, dtype=x.dtype) y_ref = x @ W y_raw = quantize_dequant_symmetric(x, bits=4) @ W y_rot = quantize_dequant_symmetric(x @ H, bits=4) @ (H.T @ W) print((y_raw - y_ref).abs().mean()) print((y_rot - y_ref).abs().mean())
hadamard_matrix

递归构造 H2, H4, H8..., 并除以 sqrt(n) 保证正交.

quantize_dequant_symmetric

教学版对称量化: 先量化到整数桶, 再反量化回浮点以比较误差.

H.T @ W

把逆旋转折叠进权重, 保持不量化时的 Linear 输出等价.

Practice

7. 工程注意事项

真实大模型里直接把这个 toy 公式塞进去还不够. 下面这些点通常决定收益和代价.

问题 原因 常见处理
hidden size 不是 2 的幂 标准 Hadamard 递归最自然支持 2^k 分块 Hadamard, padding, 或换其他结构化正交旋转
在线旋转有额外延迟 activation 旋转无法全部离线折叠 使用 Fast Walsh-Hadamard Transform 或 fused kernel
不能跨过任意算子 非线性和 softmax 通常不保持旋转等价 只在可证明等价的 Linear 边界插入旋转
不是万能降误差 收益依赖校准数据, 分布和量化粒度 结合 group-wise scale, clipping, mixed precision fallback

Summary

8. 一句话记住

Hadamard 变换是低成本的正交数值整形工具. 它把集中在少数维度的 outlier 混合到更多维度, 让低比特量化更容易; 它不负责压缩参数, 而是帮助量化器看到一个更友好的分布.

记忆版: 量化前先旋转, outlier 被打散; 不量化时等价, 量化时误差可能更小.
