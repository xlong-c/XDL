## 提交代码

### 步骤

1. **检查状态** - 查看未跟踪和修改的文件
2. **添加文件** - 将相关文件添加到暂存区
3. **提交更改** - 使用纯净的中文提交信息（不包含 AI 标记）
4. **推送到远程** - 将提交推送到远程仓库

### 提交信息规范

使用简洁的中文描述，遵循以下格式：

```
<类型>: <简短描述>
```

**常用类型**：
- `添加`: 新增功能、文件、代码
- `修复`: 修复 bug、错误
- `更新`: 更新现有功能、逻辑
- `优化`: 性能优化、代码改进
- `重构`: 代码重构、结构调整
- `删除`: 删除功能、文件
- `文档`: 文档更新

**示例**：
- `添加: 实现用户认证功能`
- `修复: 解决登录超时问题`
- `优化: 提升数据库查询性能`
- `更新: 改进错误处理逻辑`

### 执行顺序

```bash
# 1. 查看状态
git status

# 2. 查看具体改动（可选）
git diff

# 3. 添加文件
git add <files>  # 或 git add . 添加所有更改

# 4. 提交
git commit -m "<类型>: <描述>"

# 5. 推送
git push
```

## 拉取代码

### 步骤

1. **拉取更新** - 从远程仓库拉取最新代码
2. **处理冲突**（如有） - 解决合并冲突
3. **确认状态** - 验证拉取结果

### 执行命令

```bash
# 拉取当前分支的最新代码
git pull

# 如果有冲突，解决后：
git add <resolved-files>
git commit
```

## 注意事项

- **纯净提交**: ⚠️ **重要** - 提交消息中不包含任何 AI 标记、签名或归属信息
- **提交前检查**: 确认只提交相关文件，避免提交敏感信息（如 .env、密钥等）
- **简洁描述**: 提交信息应清晰说明做了什么，不需要解释为什么
- **频繁提交**: 小步快跑，每次完成一个小功能就提交
- **格式示例**: 使用 `git commit -m "类型: 描述"` 即可，不要添加任何额外内容

## 正确示例

```bash
# ✅ 正确 - 纯净提交
git commit -m "添加: 实现用户认证功能"

# ❌ 错误 - 包含 AI 标记
git commit -m "添加: 实现用户认证功能

🤖 Generated with Claude Code
Co-Authored-By: Claude <noreply@anthropic.com>"
```
