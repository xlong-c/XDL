XQT 压缩与部署阅读页

这是 xqt/ 的阅读版入口, 只提炼当前源码和 docs/md/XQT.md 的事实. 先看入口和流水线, 再看 recipe 和后端边界.

XQT 仍是实验包. 当前已覆盖 CPU smoke, ONNX Runtime QDQ, PyTorch native export, CUDA FP8 recipe, TensorRT dry-run 和 HF 文本蒸馏/剪枝支架.

一. 入口

运行 recipe

xqt-run-recipe 读取 XQT_CONFIG, 默认使用 xqt/recipes/smoke_cpu.yaml, 不解析命令行参数。

预检 recipe

xqt-preflight 读取同一配置, 输出 JSON 检查报告, 用于先确认 target, 依赖, 可执行文件和 CUDA 条件。

顶层 API

xqt.load_xqt_config, xqt.run_xqt_recipe, xqt.preflight_xqt_config 和 XDL adapter 入口目前列为 Provisional。

三. 关键模块

core

配置, manifest, registry

xqt/core/schema.py 定义 recipe schema v1, xqt/core/config.py 负责 OmegaConf 加载, xqt/core/artifact.py 记录 checksum 和产物, xqt/core/registry.py 提供 pass, recipe, exporter registry。

pipeline

runner 与 pass

xqt/pipeline/runner.py 负责组装默认 pass 顺序, xqt/pipeline/passes.py 实现 load, eval, prune, quant, export, benchmark, report。

quant

torchao 与 ONNX QDQ

当前量化主线是 quant/torchao_backend.py, quant/onnx_qdq.py, quant/calibration.py 和 quant/sensitivity.py。

export

导出后端

已接入 torch.export, TorchScript, ONNX, TensorRT trtexec, OpenVINO, ExecuTorch, ncnn 和 MNN 的适配层。

distill

蒸馏与 HF 文本支架

distill/losses.py, distill/training.py, distill/hf_text.py 负责 teacher-student 蒸馏和文本分类 bundle。

xdl

XDL 对接

xqt/xdl_adapter.py 把 XDL TrainSetup 或 checkpoint 转成 XQT context, 方便把训练产物接到压缩流水线。

四. 当前 recipe

Recipe 用途 状态
smoke_cpu.yaml CPU smoke, PyTorch native export, manifest 最小闭环, 当前默认入口。
image_resnet_onnx_qdq_int8.yaml ResNet/CNN, ONNX Runtime QDQ, TensorRT dry-run 用于验证 ONNX 导出和 QDQ 量化路径。
image_resnet_cifar100_qdq_cpu.yaml 本地 CIFAR-100, ONNX Runtime QDQ, benchmark 真实数据链路, 仍偏验证性质。
image_vit_torchao_fp8.yaml ViT, torchao FP8, sensitivity report 当前默认使用 cuda:0, 可直接跑 quant + benchmark. 真实任务精度仍需目标数据验证。
prune_finetune_cpu.yaml 线性剪枝 schedule + KD 微调 验证剪枝后恢复流程。
hf_text_kd_prune.yaml HF 文本分类, KD, pruning 需要 transformers 和 datasets。
