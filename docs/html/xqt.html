XQT 模块导览

XQT 是本仓库的模型压缩, 图变换与部署工具链. 它只处理模型本身: 量化, 剪枝, 算子优化, 导出, 误差分析与 benchmark. 训练, QAT, finetune, distillation, recovery, dataset / dataloader 和 task-level validation 不属于 XQT.

本页是人类阅读层. 行为与契约以源码, architecture/xqt.md, usage/xqt-workflows.md 和 xqt/FRAMEWORK.md 为准.

一. 定位与主链路

XQT 消费训练后的模型 / checkpoint / 导出产物, 产出优化模型, 导出目标, report 与 manifest.

输入
nn.Module
checkpoint
export artifact 编排
Session
或 YAML
optimize_model 变换 stage
quant / prune
operator 导出 stage
export / deploy 观测 stage
analyze
benchmark 落盘
artifacts
manifest
report

负责什么

  • 模型侧压缩: PTQ / QDQ / weight-only / 剪枝 / 稀疏.
  • 算子与语义块 lowering: xqt.convert, xqt.nn.*, operator engines.
  • 导出适配: ONNX, TensorRT, OpenVINO, torch.export, TorchScript, ExecuTorch, ncnn, MNN.
  • 模型侧分析与基准: output diff, layer analysis, latency / memory.
  • 产物追踪: ArtifactManifest, stage report, readiness.

明确不包含

  • 训练循环 / trainer / training provider.
  • QAT / finetune / distill / recovery.
  • dataset / dataloader 构建.
  • task-level validation (accuracy / mAP 闭环).
  • 替代 TensorRT / ORT / OpenVINO 等官方 runtime 本体.

二. 主要模块总览

包根目录 xqt/. 顶层导出进入 Provisional API; 子模块内部实现按 Internal 处理.

模块 路径 职责 内容物要点
workflows xqt/workflows/ Stage 编排主链. Session 与 optimize_model 都落在这里. optimization.py (Session / optimize_model), stage.py, stage_specs.py (装配与校验), stage_provider.py, session_runner.py, session_targets.py
core xqt/core/ 结构化配置, StageSpec, workflow schema, 产物 manifest 与 reporting. schema.py, stage_specs.py, workflow_schema.py, artifact.py, reporting.py, types.py, errors.py
contracts xqt/contracts/ Stage payload, 存储协议与 reference 语义. runtime 显式 materialize execution view. quantized.py, pruned.py, runtime.py, module.py, channel.py, compute.py, int8_mma.py, w4_storage.py
pipeline xqt/pipeline/ Pass 执行, preflight, export pass 与 runner. passes.py, export_pass.py, preflight.py, runner.py, export_handlers/
compression xqt/compression/ 模型侧压缩唯一落点. quantizer 只产出 contracts storage, 不 import runtime. quant/ policy / plan / quantizers / calibration; prune/ unstructured / structured / N:M / block sparse

conversion xqt/conversion.py (公开别名) + xqt/kernels/nn/conversion/ xqt.convert(...) 入口与模块级 lowering 实现. PrecisionPolicy, converter, linear / attention / feedforward / block 实现
export xqt/export/ 导出 adapter: ONNX / TRT / OpenVINO / torch / mobile 等. onnx_exporter.py, trt_*.py, openvino.py, torch_exporter.py, mobile.py, lowering.py, fusion.py
runtime xqt/runtime/ 混合推理引擎与标准模型包加载. 只消费已量化 artifact 与 execution policy. engine.py (HybridInferenceEngine), policy.py, channel.py, package.py
analysis xqt/analysis/ 张量 diff, layer analysis, SVD, report helper. compare.py, layer_analysis.py, svd_analysis.py, report.py, detection.py
kernels.wrappers.bench xqt/kernels/wrappers/bench/ latency / memory 基线与 profiler 记录辅助. 顶层 benchmark/ 已删除. latency.py, memory.py, phase_latency.py, profiler.py
kernels.nn.fixtures xqt/kernels/nn/fixtures/ smoke 模型 helper, family 分类与 forward hook 采集. 顶层 model/ 已删除. hooks.py, families.py, toy_models.py, smoke_*.py
readiness xqt/readiness.py 场景 readiness 汇总: capability matrix 与 report 落盘. assess_xqt_readiness(), XQTReadinessReport
xdl_adapter xqt/xdl_adapter.py 从 XDL TrainSetup / checkpoint 提取模型上下文. 不接管训练. xdl_setup_to_xqt_context, xdl_checkpoint_to_xqt_context, load_checkpoint_into_model
recipes xqt/recipes/ 声明式 stage workflow YAML 示例与可复现实验. quant/, prune/, operator/, detection/, smoke/, analysis/

三. 关键子系统内容物

量化, 算子引擎, runtime 是最常改的三块, 先按目录理解职责切分.

3.1 compression/quant 分层

schema / plan

policy.py, strategy.py, plan.py, types.py, capability.py, selection.py, sensitivity.py

描述谁可量化, 怎么选层, 如何组 plan 与 report.

quantizers/

模型侧算法: FP4 weight-only, MXFP, ConvRot W4A4, AWQ/GPTQ, INT8 MMA, W4 storage + INT8 MMA, SVD, fake QDQ.

execution/

plan dispatch, component 执行, report 组装. 不直接做 kernel.

backends/

外部适配: torchao, onnx_qdq, bitsandbytes, transformers, planned 后端.

calibration/

activation 统计, drift, calibration summary. 数据由调用方传入.

artifact boundary

量化器产出 xqt.contracts storage shell; runtime 通过显式 materializer 构造 execution view.

3.2 kernels operator 分层

ops/_impl/engines/

schema 中的 OPERATOR_OPT_ENGINES: torch_compile, deployment_engine, triton, tilelang, cutile, cutlass, cute_dsl, custom_cuda.

另有 gemm_precision / gemm_selector. 这些是 XQT engine, 不是外部 inference backend.

ops/_impl/

pattern 级实现: attention, conv, linear, gemm, prepack; 只处理 tensor 计算与 pattern metadata, 不直接承载语义 facade.

wrappers/

execute.py, materialize.py, capability.py, plan.py, reference_wrappers.py, triton_wrappers.py. 它们是 facade 和 kernel 之间的边界翻译层.

3.3 runtime 分层

HybridInferenceEngine

engine.py: 模块级 / 通道级混合精度调度. 不跑 quantizer / calibration / sensitivity.

execution policy

policy.py + channel.py: 应用 compute precision 与 channel hybrid mask; dual-path reference 前向.

模型包

package.py: load_model_package() / create_inference_runner(). 最小闭环为 *.xqtpkg/manifest.json + runtime/config.json, 现阶段保证 ONNX + ORT.

3.4 contracts 与 payload kind

payload kind 典型 stage 含义
torch_module baseline / 默认模型态 可恢复的普通 nn.Module.
quantized_model quant QuantizedModelPayload: 模型 + lineage + artifacts + capability.
pruned_model prune PrunedModelPayload: 模型 + sparsity report + execution state.
runtime_plan operator RuntimePlanPayload: operator 优化计划与 materialize 结果.
export_bundle export / 未 materialize 的 deploy ExportBundlePayload: 导出产物集合.
runtime_handle materialized deploy RuntimeHandlePayload: 可执行 ORT session 或 TRT context.
stage_report benchmark / analyze 观测报告, 不进入可恢复模型快照.

Session transform-side provider 在 xqt/workflows/stage_provider.py: DefaultStageProvider, ModelQuantizerProvider, ModelPrunerProvider, OperatorOptimizerProvider, ExportProvider, ObservationProvider. 另: workflow 的 transform kind (quant / prune ...) 与 session 内部 StageKind (baseline / quantized / optimized / observed / exported ...) 是两套枚举, 由 stage_kind_for_transform() 映射.

四. 术语: backend 与 engine

文档和 recipe 必须区分这两个词, 不要混写.

backend (外部选择)

  • quant: torchao, pytorch, onnxruntime_qdq ...
  • export / deploy runtime: TensorRT, ONNX Runtime, OpenVINO, ExecuTorch, ncnn, MNN
  • 写在 quant.params.backend, hardware.backends, export target 配置里

engine (XQT 内部实现)

  • torch_compile, deployment_engine, triton, tilelang, cutile, cutlass, cute_dsl, custom_cuda
  • 出现在 xqt.convert(..., engine=...), operator targets, capability / StageReport
  • 不是与 TensorRT 并列的 "外部推理后端"

成熟度字段 maturity 统一为 executable / reference_guarded / metadata_only / planned. package 可导入或 capability 显示 executable, 不等于本机已完成 correctness / 性能验收.

五. 配置方案 (只有两种)

原则上不新增 CLI 参数解析, JSON 硬编码 workflow 或其他平行配置路径.

第一配置: XQTOptimizationSession

Python 交互式 stage 编排. 适合探索, 调试, notebook, 动态拼装流程.

from xqt import XQTOptimizationSession

session = XQTOptimizationSession(
    model=model,
    example_inputs=example,
    calibration_inputs=calib,
    project={"name": "demo", "artifact_dir": "artifacts/xqt/demo"},
    device="cuda",
)
session.benchmark(name="baseline", warmup=5, iterations=20)
session.quant(
    name="ptq_int8",
    backend="torchao",
    strategy="weight_only_int8",
    policy={"dtype": "int8", "scheme": "weight_only"},
    compare_to="baseline",
)
session.export(name="to_onnx", format="onnx", output_path="out.onnx")
result = session.result()

第二配置: YAML workflow

声明式 recipe, 经 optimize_model() 或 xqt-run-workflow 运行. 适合可复现批量实验.

from xqt import optimize_model

result = optimize_model(
    "xqt/recipes/smoke/smoke_workflow.yaml",
    model=model,  # 可选, 也可写在 YAML model 字段
    example_inputs=example,
)

5.1 YAML 顶层字段 (唯一 schema)

字段 含义
project 项目名与 artifact_dir. 优化模型, 导出产物, report, manifest 都落这里.
model 输入模型 / checkpoint 信息; 也可由 optimize_model(..., model=...) 传入对象.
task 模型侧 task metadata only. 不声明 dataset 或 evaluation provider.
compression_axes 本次优化轴. schema 常量: width, depth, precision, sparsity, steps, low_rank.
hardware 设备与 backend 约束, 如 device, backends.
benchmark workflow 默认 benchmark 参数.
stages 唯一优化与导出路径. quant / prune / operator / export / deploy / benchmark / analyze 只能作为 stage.
device 可选简写设备字段 (与 hardware 配合使用).

已删除的旧顶层字段不要再写: compression, export, operator_optimization, analysis, validation, config_version. 旧 XQTConfig / load_xqt_config / run_xqt_recipe 入口也已删除.

5.2 支持的 stage kind

benchmark prune quant operator export deploy analyze
  • 不支持: finetune, distill, eval, runtime_eval, qat_train, recovery.
  • 量化 recipe 必须显式写 backend 与 policy.
  • calibration_inputs / example_inputs 由调用方传入, recipe 不声明数据来源.
  • Session 初始化会注册 baseline; use(name) / revert_to(name) 只恢复模型 snapshot, 不把 export bundle 当模型.

5.3 最小 YAML 示例

project:
  name: smoke_workflow
  artifact_dir: artifacts/xqt/smoke/workflow
model:
  target: torch.nn.Linear
  params:
    in_features: 4
    out_features: 2
compression_axes:
  - sparsity
hardware:
  device: cpu
  backends: []
stages:
  - name: prune_l1
    kind: prune
    params:
      method: global_l1_unstructured
      target_sparsity: 0.5

5.4 export / deploy 目标字段落点

已知字段写在 typed 子对象里, 不要塞回 target params (loader 会拒绝同名旧键).

目标 配置路径 常见字段
ONNX targets[*].onnx input_names, output_names, dynamo, validate, runtime_diff, pre-export fusion/lowering, optimization
TensorRT targets[*].tensorrt onnx_path, trtexec_path, dry_run, workspace, plugins, runtime_benchmark ...
OpenVINO targets[*].openvino onnx_path, input_shape, dry_run, runtime_diff, device
TorchExport targets[*].torch_export strict, validate, runtime_diff
TorchScript targets[*].torchscript method (trace/script), check_trace, runtime_diff
ExecuTorch / ncnn / MNN targets[*].executorch / .ncnn / .mnn converter 路径, dry_run, source_path, timeout 等
runtime handle runtime_handle.onnxruntime / .tensorrt ORT providers; TRT device 与 runtime plugin libraries (不从 engine-build 隐式继承)

六. 使用方式

公开入口以 Python API 为主; CLI 只是薄封装.

6.1 公开入口一览

入口 用途
from xqt import XQTOptimizationSession 第一配置: 交互式 stage 编排.
optimize_model(path_or_config) 第二配置: 跑完整 YAML / dict workflow.
load_optimization_config(...) 加载并解析为 OptimizationConfig + typed StageSpec.
xqt.convert(module, engine=..., policy=...) 单模块 / 小范围 semantic conversion.
xqt.nn.Linear / Conv2d / LayerNorm / FeedForward / RMSNorm / Attention / TransformerBlock 带 engine / precision intent 的 facade. 它们不是 kernel catalog, 真正的 engine 执行仍经 materialize / wrapper 进入 pattern 级 kernel. Attention / TransformerBlock 当前 engine 以 torch / tilelang 为主, 不是完整 block-level 生产 megakernel.
assess_xqt_readiness() 环境与场景 readiness 审计.
xqt.runtime.load_model_package() / create_inference_runner() 文件侧推理加载 (标准模型包).
xdl_setup_to_xqt_context / xdl_checkpoint_to_xqt_context 从 XDL 产物衔接模型上下文.
xqt-run-workflow 安装后的 workflow CLI 薄入口.

6.2 Session 常用方法

变换

prune(), quant(), operator()

支持 from_stage, compare_to, accept, revert_on_reject.

导出

export(), deploy()

单 target 可用 format= / typed kwargs (onnx=, tensorrt= ...); 多 target 用 targets=.

观测与状态

benchmark(), analyze(), readiness()

compare_stages(), compare_to_baseline(), use() / revert_to(), result()

6.3 convert + nn facade 短例

import xqt
from xqt.kernels.nn import FeedForward

ffn = FeedForward(dim=512, hidden_dim=2048)
converted = xqt.convert(
    ffn,
    engine="triton",
    policy={"activation": "fp16", "weight": "fp16", "mma": "fp16", "accum": "fp32", "output": "fp16"},
)
# converted 保留 contract metadata; CPU / kernel 不可用时会记录 eager fallback

6.4 文件推理闭环

from xqt.runtime import load_model_package, create_inference_runner

pkg = load_model_package("path/to/model.xqtpkg")
runner = create_inference_runner(pkg)
outputs = runner.run(inputs)

workflow 的 ArtifactManifest 用于实验追踪, 不是推理加载契约. 推理侧只消费标准模型包 manifest.json.

七. recipes 内容物

所有 YAML 必须是 stage workflow, 且能被 load_optimization_config() 加载.

quant/

int8 / int4 / fp8 等量化示例. 如 ResNet QDQ, torchao FP8, ConvRot W4A4 smoke.

prune/

structured / unstructured / block_sparse. CNN / ViT 剪枝与 sparsity report.

operator/

按 engine 分层: torch_compile, triton, tilelang, cutlass, cutile 等.

detection/

检测模型部署与 TRT / QDQ 实践 (YOLO, RT-DETR 等).

smoke/

综合冒烟: CPU workflow, weight-only + TileLang + ONNX/TRT golden 等.

analysis/

层统计与 quant layer analysis 类 workflow.

不要新增训练 recipe (finetune / distill / recovery / QAT train). 这类流程放 XDL 或外部训练工具.

八. 能力状态与工程约束

阅读页只提炼当前事实, 不把 planned 写成已完成.

已基本可用

PTQ / QDQ / torchao, 常规剪枝, ONNX / torch.export / TorchScript / TRT / OpenVINO / ExecuTorch / ncnn / MNN 导出适配, output diff, layer analysis, latency/memory, manifest.

半可用 / 受限

TRT plugin preflight, TileLang 受限 kernel (attention / linear / dequant GEMM 等), FP4 packed bridge, CuTile / CuTe DSL 的 reference-guarded 路径.

偏实验

更完整 AWQ/GPTQ packed megakernel, 更广 engine capability 闭环. Attention / TransformerBlock 已是 facade, 但 block-level 完整 fusion 性能声明仍未成立.

  • 新能力必须服务模型本身: quant, prune, operator, export, diff, benchmark, manifest.
  • TensorRT / OpenVINO / ncnn / MNN / ExecuTorch 以目标机官方安装为准; XQT 只做 adapter 与 preflight.
  • 真实 FP8 / FP4 收益必须在支持硬件上验证; synthetic smoke 只做本地闭环.
  • benchmark 给基线, profiler 给瓶颈归因; 二者在 report 中不可混为一个指标.
