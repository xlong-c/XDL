两类文档

同一套事实,两种读法. docs/md/ 是工作台,docs/html/ 是阅读地图.

Codex

MD 工作文档

位于 docs/md/. 面向写代码和维护框架,内容更密,更靠近源码契约,适合快速查入口,生命周期,配置字段,API 边界和测试要求.

查看 MD 索引
User

HTML 阅读版

位于 docs/html/. 面向顺畅阅读和整体理解,用更清楚的结构,卡片和表格解释概念,帮助你先看懂框架,再决定要深入哪篇 MD.

查看 HTML 页面
Rule

事实源规则

行为,字段,API 和兼容承诺以源码和对应 MD 为准. HTML 可以提炼和重排,但不能和 MD 或源码产生冲突.

推荐阅读路线

第一次看 XDL 时,按这条路走. 每一步都可以直接跳到高密度 MD.

1
安装和验证 确认环境,依赖,可运行入口和基础测试命令.
README.md#安装
2
框架是什么 理解 XDL 的定位,核心分层,训练入口和生命周期.
README.md#框架
3
怎样写 YAML 理解 setup_from_yaml(),schema v1 和 target + params 组织方式.
README.md#配置
4
怎样接数据集 先看模板选择,再看通用 dataset 模块结构图.
README.md#数据集
5
哪些 API 稳定 区分 Stable, Provisional 和 Internal,避免依赖内部实现.
README.md#API
6
模块边界和后续方向 查子模块职责,再看当前仍有效的优化计划.
README.md#边界
7
XQT 压缩与部署 查看量化,蒸馏,剪枝,扩散少步蒸馏和部署导出的长期工作文档.
XQT.md

写代码前看什么

改动不同区域时,优先回到对应 MD. 这也是 Codex 修改代码前应使用的路线.

改动范围 先读 目的
训练生命周期,Trainer,CoreModel,Callback README.md#框架 确认手动优化,batch 迁移,日志和回调顺序.
YAML 配置,schema,target + params README.md#配置 确认配置主链路和 OmegaConf 约束.
数据集模板,collate,manifest README.md#数据集 确认应该复用模板,新增 thin adapter,还是只新增 transform/collate.
公开入口,导出符号,兼容策略 README.md#API 确认 Stable / Provisional / Internal API 边界.
目录职责或模块迁移 README.md#边界 确认逻辑应该放在哪个子模块.
xqt/ 量化,蒸馏,剪枝,扩散少步蒸馏和部署格式导出 XQT.md 确认工具链边界,模块拆分,产物规范和任务排期.

维护规则

当框架行为,配置字段,注册名称或 API 边界变化时,先更新对应 MD 和测试. 如果 HTML 页面覆盖了同一主题,再同步更新 HTML,确保好读版不漂离真实实现.
