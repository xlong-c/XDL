# docs - 仓库文档目录

## 目录职责

- 存放 XDL 框架本身的长期文档.
- 将文档分成两类: `*.md` 是 Codex 和开发者写代码前看的高密度工作文档,`html/` 是面向用户阅读的可视化文档.
- 为仓库读者提供安装,结构,配置,API 边界,数据集模板和模块边界说明.
- 不承载研究笔记,一次性分析和临时草案.

## 当前内容

- `README.md`: 文档索引,同时说明 MD/HTML 分层.
- `INSTALL.md`: 安装说明.
- `CONFIG.md`: 配置系统说明.
- `DATASET.md`: dataset 模板规划,选择和扩展方式.
- `API.md`: Stable / Provisional / Internal API 边界和兼容策略.
- `XDL.md`: 框架结构与使用说明.
- `xdl-functional-boundary.md`: 模块职责速查.
- `xdl-optimization-plan.md`: 当前仍有效的优化方向.
- `html/index.html`: 面向用户阅读的 HTML 总入口.
- `html/dataset-structure.html`: 通用 dataset 模块结构说明,不包含 hair 特殊数据集.

## 修改约束

- 文档内容优先与真实代码保持一致,不写脱离实现的理想化描述.
- 涉及 API,目录,生命周期时,先回查源码再更新文案.
- 涉及公开 API,导出符号或兼容承诺时,必须同步检查并更新 `API.md`.
- 大改动时同步更新交叉引用和索引页.
- 规划文档与现状说明要区分清楚,避免混写.
- `docs/` 只保留长期有效内容;阶段性调研优先放 `research/`.
- HTML 页面是阅读层,不作为唯一事实源;同一主题的 MD 事实变化时,必须同步对应 HTML.
- 新增 HTML 页面默认放在 `docs/html/`,保持静态自包含,避免依赖外部 CDN.

## 写作建议

- 每篇 MD 文档先写清楚这篇文档负责什么,不负责什么.
- MD 优先写入口,边界,限制,检查清单和验证方式.
- HTML 优先面向阅读路径和概念理解,可以重排内容,但不要改写事实边界.
- 避免多个文件重复讲同一套架构背景.
