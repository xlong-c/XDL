# XDL Agent Usage

这是一份给 agent 看的入口说明. 先读完, 再向项目方提问, 再写代码. 不要先猜路径, 再用一堆中转层补救.

## 先做什么

1. 先确认这次要改的是训练入口, 配置加载, 数据准备, 还是工具入口.
2. 先确认实现风格是显式代码, YAML 驱动, 还是沿用现有入口.
3. 先确认路径和产物是否统一放进单个 `run_dir`.
4. 先确认默认保存范围是 adapter, preview, 还是全量 checkpoint.
5. 先确认这次改动只服务当前仓库, 还是要保留 wheel 安装后的跨仓库复用.

## 应该怎么问

每个问题都要带推荐默认值. 不要让项目方自己补齐实现细节.

建议直接按下面顺序提问:

1. 这次改动主要服务哪类任务?
   - 推荐默认: 训练.
   - 目的: 先把入口边界锁定, 再决定是动 `Trainer`, `CoreModel`, 还是只动脚本和文档.

2. 你希望 agent 采用哪种实现入口风格?
   - 推荐默认: 显式代码.
   - 目的: 先决定是把逻辑留在 Python API, 还是让 YAML 承担更多选择.

3. 路径和产物应该怎么管理, 才最方便后续维护?
   - 推荐默认: 单个 `run_dir`.
   - 目的: 统一 `logs`, `checkpoints`, `previews`, `resolved_config` 等派生路径, 减少临时中转目录.

4. 训练过程中默认保存哪些产物?
   - 推荐默认: adapter + preview.
   - 目的: 既保留可复用结果, 又能快速检查训练状态.

5. 哪些事情允许 agent 自动补全, 哪些必须显式确认?
   - 推荐默认: 仅补默认值.
   - 目的: 防止 agent 在不确认偏好的情况下擅自改行为.

## 需要让 agent 明白的底线

- 不要先写实现, 再反向猜项目偏好.
- 不要在入口里制造多层路径中转, 除非项目方明确要求.
- 不要把临时兼容写成新习惯.
- 不要为了“方便”把隐式推断放进核心入口.

## 写完以后要给出的东西

- 明确的实现方案.
- 明确的路径约定.
- 明确的默认值和假设.
- 明确的测试范围.

## 包内入口

```bash
xdl-usage
python -m xdl.usage
```

Python 里直接读:

```python
import xdl

text = xdl.get_usage_text()
```
